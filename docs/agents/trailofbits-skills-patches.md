# Trail of Bits skills — local patch ledger

Every local change applied to a vendored skill from
[trailofbits/skills](https://github.com/trailofbits/skills), one row per patch id per touched file.
**Six patch ids across 21 touched files**, giving 22 rows, plus one final row for a file **exclusion** that
carries no patch id because a deleted file cannot hold a marker.

Each change is marked in the vendored file itself with `<!-- bukerov-local-patch: <id> -->`, in two forms
that both appear in this set: the **paired wrapping** form
`<!-- bukerov-local-patch: <id> --> … <!-- /bukerov-local-patch: <id> -->` around the changed text, and the
**self-closing single-line** form `<!-- bukerov-local-patch: <id> — <note> -->` placed immediately above or
in place of what changed. Every file in this set is Markdown, so the Python `# bukerov-local-patch:` form
used in other providers' ledgers does not appear here. Two ids carry no in-file marker at all, for reasons
stated in their rows: `tob-mode-normalize` (a file mode cannot hold a comment) and the `openai.yaml`
exclusion (a deleted file cannot hold one either).

All unpatched content is **byte-identical** to upstream commit
`4db88ee79db0a68bbe049fe827e272ee2bc19510` (see `trailofbits-skills-manifest.json` for each file's
`upstream_blob_sha` and `vendored_blob_sha`). Verified by diffing all 206 vendored files — 183
upstream-origin plus 23 verbatim `LICENSE` copies — against a read-only clone at that commit: exactly the
18 content-modified files listed below differ, every one of the remaining 188 is identical byte for byte,
and every `vendored_blob_sha` in the manifest matches `git hash-object` on disk.

No translations, no stylistic rewrites, no reworded guidance. Every change here is one of: a pointer to a
plugin runtime this project-local install does not have, a pointer to something that is not installed, a
path segment made wrong by relocating a file, an invisible Unicode character this repository forbids, a
file mode, or a git command that mutates the working tree. **No patch caps concurrency, imposes a writer
count, forces a reviewer into a read-only role, or changes any skill's agent topology** — see
`trailofbits-skills-policy.md`, "Default: minimal patching".

here are adaptations of BY-SA material and are themselves CC BY-SA 4.0, not GPL-3.0.

## Not patched, deliberately

Recorded so nobody looks for a ledger row that does not exist, and so a future re-vendor does not "fix"
something that was a decision:

- **`{baseDir}` is kept verbatim everywhere else.** Trail of Bits' own documented convention (upstream
  `AGENTS.md:132`) for "this skill's own directory", used in hundreds of lines across the set. The
  validator resolves it against the skill root (`resolve_skill_link`) rather than the vendoring rewriting
  it. The only files where it was touched are the four relocated agents, whose paths were written from
  plugin root and were genuinely one segment wrong; after that, the string `{baseDir}/skills/` appears
  nowhere in the vendored tree.
- **No agent topology, fan-out width, writer count, reviewer lane or repair loop was altered.**
  `fp-check`'s three subagents are byte-identical to upstream; `audit-context-building`'s
  one-subagent-per-function dispatch is unbounded, as upstream wrote it; `spec-to-code-compliance`'s
  independent-refuter requirement and `variant-analysis`'s looping parallel sweep are intact. Where
  `tob-no-plugin-workflow` touched those skills it replaced a missing command with the equivalent `Task`
  dispatch and preserved the fan-out, rather than narrowing it.
- **`trailmark/SKILL.md`'s `uv pip install trailmark` instruction is unpatched**, unpinned and
  network-reaching, as is `semgrep/scripts/run-scans.sh`'s runtime cloning of third-party rule
  repositories. These are runtime dependency decisions for whoever invokes the skill, not authority
  boundaries this vendoring may quietly decide — both are documented in the policy's "Supply-chain
  assumptions" instead.
- **`differential-review/patterns.md`'s surviving `building-secure-contracts/development-guidelines`
  bullet.** It names an upstream plugin that exists at the pin but is not installed here, which is a
  different thing from the five dead paths removed alongside it. Left in place; flagged in the policy's
  "Known limitations".
- **`plugins/trailmark/agents/code-slice-worker.md` was not relocated.** Its only consumer,
  `slicing-code-context`, is excluded, so vendoring it would have added an orphan definition no installed
  skill dispatches. Seven agents were relocated, not eight.
- **`harness-writing`'s `type: technique` frontmatter key.** Trail of Bits' own skill-kind marker,
  meaningless to Claude Code and harmless; registered in this provider's `extra_frontmatter_keys` allowlist
  rather than stripped to satisfy a key check.
