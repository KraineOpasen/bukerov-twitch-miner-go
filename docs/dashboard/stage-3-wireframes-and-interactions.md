## 4. Сохранённые решения Stage 2 (дословно соблюдены)

1. **Ровно два текущих слота** везде (сайдбар, Обзор, Очередь, мобайл-стек); пустой слот — определённое состояние «Слот свободен + причина», не скрывается.
2. **Полный ростер обязателен** в Очереди и назначениях (плотная таблица + карточная трансформация).
3. **Claims/History — единственный владелец** жизненного цикла клейма; другие страницы только ссылаются.
4. **Save/Cancel/Discard по категориям**: категория = граница грязного состояния; липкая панель; Discard-диалог при уходе; **autosave запрещён**.
5. **Аккаунт-уровневые персистентные звуковые предпочтения** (BD-B4) + **браузерное fail-open воспроизведение** (сбой звука не блокирует майнер и заявлен в UI).
6. **Ручные органы отложены** (DPBA, §11 ниже) — без фальшивых серых кнопок.

## 5. Словарь состояний (13)

S-LOAD скелет фиксированной геометрии, `aria-busy` · S-READY данные+свежесть · S-EMPTY «пусто»+почему+первый шаг · S-PART «часть недоступна: что именно» · S-STALE данные+возраст+метка · S-UNK «неизвестно», мутации отключены с причиной · S-DEGR «работает частично»+причина · S-FAIL «сбой»+причина+время, `role=alert`, Retry · S-BLOCK «заблокировано браузером»+как включить · S-DENY «разрешение отклонено»+шаги · S-NOBACK контрол **не рендерится** (не «серый») · S-SESS метка «свидетельство этой сессии» · S-DEFER пассивная запись «отложено до аудита».
**Инвариант:** unknown никогда не конвертируется в healthy/completed/claimed/delivered.

## 6. Поведение loading/empty/stale/degraded/unknown/error

- Загрузка: скелеты фиксированной высоты, без сдвига макета, без live-спама.
- Пусто: приглашение к первому действию (ссылка), пусто ≠ ошибка.
- Устарело: возраст у блока + глобальный индикатор в шапке; решения по устаревшему — с предупреждением.
- Деградация: баннер причины + ссылка на Диагностику/Логи (с префильтром подсистемы).
- Неизвестно: текст «неизвестно» + иконка; зависящие мутации отключены с причиной; переход к диагностике.
- Сбой: инлайн `role=alert` в месте сбоя (не toast), ручной Retry; авточастоты не изобретаются.

## 8. Матрица взаимодействий/навигации (сводка)

Серверный первичный рендер; HTMX только для фрагментов со стабильными `hx-target`-границами (lifecycle, слоты, очередь, логи, списки дропсов, журнал, статус-виджеты). Мутации: `hx-disabled-elt`+`hx-sync` (CP). Подтверждения: лёгкие `hx-confirm`, тяжёлые — модальные. Ошибки инлайн, toast только для успеха. Фокус после свапа → контейнер `tabindex="-1"` + `data-*-announce` (CP). Глубокие ссылки на страницы/категории/фильтры; фильтры → query-параметры (`replaceState`). Транспорт: паритет — SSE статуса и 10-с поллинг логов; новые зоны — транспортно-независимый UI-контракт (свежесть + ручное «Обновить»), WebSocket/EventSource не изобретаются. Ссылка всегда ведёт к владельцу факта (Обзор→Очередь→Глоссарий; Дропсы↔Claims↔Журнал; События→Настройки; Настройки/system→Система; S-DEGR/S-FAIL→Логи).

## 12. Владельческое решение №1

**Глубина истории Claims/History** (открытый вопрос №2 Stage 2; персистентность не подтверждена — B2):
